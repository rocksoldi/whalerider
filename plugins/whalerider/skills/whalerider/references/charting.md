# MCP charting tools

Choose the tool matching the requested visual. Discover the current schemas from the connected server; tool prefixes vary by client.

| User request | MCP tool | Selection |
| --- | --- | --- |
| Annual returns or another annual performance metric | `chart_annual_performance` | run; optional theme, metric |
| Monthly returns heatmap or another monthly performance metric | `chart_monthly_performance` | run; optional theme, metric |
| Weekly account-value curve | `chart_equity_curve` | run; optional theme |
| Candlesticks for a completed trade | `chart_trade` | run; optional ticker, date, interval, theme |
| Simulation results in summary cards | `chart_simulation_summary` | run; optional theme |

Use an exact completed simulation run ID, not its definition ID. Resolve a supplied run reference using the appropriate lookup tools only when needed. Do not start a simulation merely to fulfill a chart request.

Annual/monthly `metric` defaults to `returns`. Friendly alternatives include `profit`, `trades`, `winrate`, `drawdown`, `sharpe`, and `sortino`, or an exact supported numeric performance field. Pass the user's requested metric; do not change metric definitions or units. The server retrieves the required periods and handles missing observations.

The default `theme` is `WhaleRider` (blue/amber); `Classic` uses green/red. Reuse the selected palette on later requests unless changed. The view's palette selector is provided by the server, not generated by the assistant.

For trade candles, `ticker` is an exact symbol and `date` is an exact UTC entry timestamp from a returned trade. Trade records do not have a trade ID. When no selection is supplied, let the tool select the latest completed trade. For a described trade, resolve its actual ticker and entry timestamp through the reporting tools when necessary; ask for clarification only if ambiguity remains. `interval` defaults to `DAY`; supported alternatives are `ONE_HOUR` and `FIFTEEN_MINUTES`. Request another trade through a subsequent tool call.

The equity curve shows Realized Account Value, excluding unrealized open-position valuations. Summary cards preserve the authoritative report's metric definitions. Interpret the returned data without inventing currency, values, or coverage.

Call the matching chart tool once per requested chart. For multiple charts or tickers, use separate sequential tool calls in the requested order: wait for each result before requesting the next chart. Never batch or parallelize chart calls; let the client render each MCP App separately. Do not execute `scripts/render_chart.py`, generate an HTML artifact or screenshot, or fetch reports to construct a second chart. A new user selection is a new chart request; a tool error is not permission to recreate the chart locally.

If a chart tool is unavailable, report that the connected server needs the charting tools. If the client cannot display the MCP App, explain that a supporting client is needed. Do not claim that successful tool execution proves visible UI rendering or provides a hosted HTML URL.
